# Claude Design System Entry Point

Before creating or modifying Dylan Cornelius / DCMLLC branded web pages or graphical assets in this repository:

1. Read `/design-system/README.md` first.
2. Read and follow `/design-system/BRAND.md` for invariant brand rules.
3. Use `/design-system/tokens.css` for canonical visual values instead of copying arbitrary legacy CSS.
4. Read `/design-system/COMPONENTS.md` for component anatomy, variants, page patterns, responsive behavior, accessibility, and component governance.
5. Use `/design-system/components.html` as the visual implementation precedent.
6. Read `/design-system/references/README.md` and use `/design-system/references/index.html` before selecting imagery, logo treatment, client proof, or visual precedent.
7. If the deliverable is channel-specific, read and follow `/design-system/SCHEMES.md`.
8. Read `/design-system/EXCEPTIONS.md` before intentionally deviating from a canonical rule.
9. If touching legacy portfolio implementation, read `/design-system/MIGRATION.md` and migrate only the intentional scope.
10. If changing the design system or running consistency checks, follow `/design-system/VALIDATION.md`; use `/design-system/validation/AGENT-TEST-PACK.md` and `/design-system/validation/SCORECARD.md` for cross-agent validation.
11. Follow the source-of-truth precedence defined in the README.
12. Treat `/design-system/AUDIT.md` as historical evidence only; it does not override canonical rules.
13. Reuse existing component contracts and approved references before inventing new visual patterns or asset schemes.
14. Correct recurring drift in the shared canonical system, not in agent-specific hidden prompt rules.
15. Do not duplicate canonical design-system prose in this file. Canonical rules belong in `/design-system/`.
